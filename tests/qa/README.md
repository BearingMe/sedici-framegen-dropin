# QA: in-game acceptance tests (P2.11)

These are the checks that need the game, a display or an external overlay. An agent
never launches the game, so you run them. Deployment and launch need your explicit
authorization each time.

Source of truth for the milestone: [MILESTONES.md](../../MILESTONES.md), section P2.11.
Known issues referenced below are in [known-issues.md](../../docs/refactor/known-issues.md).

## How to run

1. Close the game. Deploy the current build with `tools/deploy.ps1` (QA-01).
2. **Delete `sedici.log` before each test** so the log only holds the build under
   test (K101). Copy it into the test's folder right after the run.
3. Set `[log] level = 1` in `sedici.toml` unless the test says otherwise.
4. Put evidence in the test's folder, named `qa-NN-short-description/` (the ID in the
   table links to it). Name files `qa-NN-<what>.<ext>`, for example
   `qa-04-present-intervals.csv`.
5. Write what you saw in the folder's `README.md` (setup, what was done, observations,
   findings, evidence list) and fill in the Result column here (pass, fail, blocked).

## What is in git

The folder is `tests/qa/` and it is tracked, including the evidence, so every citation
in MILESTONES.md and `known-issues.md` can be followed.

- Notes and screenshots are tracked as they are. Screenshots must show only the game.
- A log is tracked as an **excerpt** (`qa-NN-sedici.log`): the settings header, create
  and destroy calls, stalls, rejections, errors, overlay events and a sample of the
  periodic statistics. The first lines of the excerpt say how many lines the full log has.
- The full log stays local as `qa-NN-sedici.full.log`, and the owner's raw notes as
  `*.original.md`. Both are ignored by git (see `.gitignore` here).
- Before adding evidence, check it for usernames and home-directory paths. Game install
  paths are fine.

## Order

Run QA-01 first and QA-15 last. QA-02 to QA-13 and QA-16 can run in any order on one deployment;
group the ones that need the same game together. QA-14 is optional. QA-17 to QA-20 are the Phase 4
sessions: QA-18 to QA-20 on Cyberpunk, QA-17 and QA-03 on Alan Wake 2. Judge their logs and captures
with `tools\analyze_log.ps1` and `tools\analyze_presents.ps1`; the verdict rules are in
[phase4-game-checklist.md](../../docs/refactor/phase4-game-checklist.md).

## Reporting a failure

Do not edit the build to make a test pass. Keep the evidence, mark the Result as
fail, and tell the agent the test ID: every defect becomes a new entry in
`docs/refactor/known-issues.md` with the evidence marked as measured.
