# Rust test parity: the C++ offline suite against the Rust suite

> **Status (2026-11-10): complete; the C++ tree is retired.** Every row below is either mapped to
> a Rust test or recorded as a `GAP`/`N/A` with its reason. The C++ sources and CTest targets named
> here were deleted from `experiment/rust`; the names are kept so the audit still reads, and a
> reader cannot run them any more. The deliberate gaps that remain are listed at the end.

This table maps every scenario group of the C++ offline tests to the Rust test that covers it, or
says `GAP` where no Rust test covers it. It is an audit, not a promise that every line moved:
the port's rule (`docs/rust/port-design.md`) is to port scenarios, not lines, so a Rust `rstest` with
one case per C++ check group is the intended shape.

It was written on 2026-11-10 on `experiment/rust`, after the ten-bit, lifecycle and refcount slices
below landed. Every Rust test named here is run by `cargo test` and skips cleanly with a message when
it needs a D3D12 adapter and none exists.

## How to read a row

- **C++ scenario** — the file and the function or named check the C++ ran. A CTest name in the
  deleted `CMakeLists.txt` (`sedici_abi_*`, `sedici_fgcheck_*`, `sedici_regression`, `sedici_gpu_*`,
  `sedici_settings_*`) is the unit the C++ recorded.
- **Rust test** — the `tests/*.rs` file, the test function, and (for a parameterised test) the
  cases. An inline `#[cfg(test)]` test is written `src/path.rs::name`.
- **GAP** — no Rust test exists. The reason is in the same cell.
- **N/A** — the check cannot exist in the port for a stated reason (a C++-only mechanism such as the
  stub-"original" DLL, an export of the original binary, or a tool that is still PowerShell).

## Gaps that are mechanisms, not scenarios

These are not missing tests; they are places where the Rust production path does not yet do what the
C++ did, so the C++ scenario cannot be reproduced. Each is a recorded `K` entry or slice boundary.
`docs/rust/port-design.md` collects the same list as the port's remaining deliberate gaps.

- **The real-frame limiter is not wired.** `application/presentation/limiter.rs` exists and its
  decisions and live reseed are tested, but nothing installs it on the wrapper's present hook or
  feeds it `live_limiter_fps()`. The C++ `limiter_before_present` runs from `dllmain.cpp`'s
  `sedici_game_present`. Hence the live-limiter rows are `GAP` on the wiring, not the policy.
- **`Router::set_present_hook` is not propagated to wrappers.** The router stores a hook, but the
  swapchain factory never reads it and no wrapper receives it. The C++ `route_set_present_hook`
  walks every wrapped chain. This is also why K60 (a hook change during creation) has no Rust case.
- **The wrapper's failure and retirement hooks (`Faults::run_wrapper_lookup_hook`,
  `run_context_record_hook`, `run_queue_recovery_hook`) have no run site.** `Faults` defines them and
  tests them, but the production path never calls them, so the K68 paused-lookup and K47/K48
  retention scenarios have nothing to drive.
- **Swapchain parking and the reaper are not ported.** The wrapper is an `Arc`; a failed drain is
  reported, not retained and reaped. The K41/K47/K48/K77 rows therefore map to the context's rules
  and the presenter's bounded drain, not to the C++ swapchain mechanism.
- **A used DLL does not pin itself.** The C++ `unload` scenario (K64) has no Rust equivalent
  (K148); the port takes no module reference and does not need one to keep its own code mapped.
- **The overlay subclass is not installed.** `window_input::capture_window_global` records the window
  and installs nothing (K156, K161), so the ABI `overlay-hotkey` scenario cannot run in Rust yet.
- **The present-hook Present1 allocation fault is not injectable in Rust.** `BookkeepingFault::
  PresentParametersAllocation` is armed by tests but nothing consumes it; the port's Present1
  metadata copy is a `Vec::clone` whose allocation failure Rust reports as a panic, which the export
  guard turns into a game-visible error. The C++ scenario's retry semantics are the same, but the
  fault cannot be forced, so it is `GAP`.

## The baseline procedure: what `tools/baseline.ps1` records

`tools/baseline.ps1` used to run the C++ CTest suite and diff its PASS/FAIL, PSNR/SSIM and
per-test verdict lines against `docs/dev/baseline.txt`. The C++ build retired, so the script now
records the Rust suite in the same shape, following this procedure (K175):

1. Run `cargo test -- --test-threads=1` from a clean `target/` (some GPU tests share one adapter and
   present to it, so serialise them). Capture stderr: the GPU tests report their figures there.
2. Record, per test binary, the `test result:` summary line — `N passed; M failed; K ignored` — and
   the sorted list of test names from `cargo test -- --list`. These are the Rust "verdicts": with
   `--test-threads=1` a failure names its test, and a skip prints a `SKIP …` line on stderr that the
   comparison must treat as "the host could not run it", exactly as the C++ `SKIP_RETURN_CODE 77`
   cases do.
3. Record the numeric lines that correspond to the C++ baseline's non-verdict lines: `tests/stage1.rs`
   and `tests/tenbit.rs` print the per-scene PSNR/SSIM; `tests/lifecycle.rs` prints the memory and
   present-queue counts; `tests/overlay_ui.rs` prints no figures but a validation-error list. These
   are the analogue of `baseline.txt`'s "PSNR/SSIM lines".
4. Do not compare wall-clock times or the absolute memory figures; compare that they exist and, for a
   thresholded test, that they pass. The C++ baseline drops timings for the same reason (K112).
5. Treat a change from `SKIP` to a verdict (or the reverse) as a difference worth explaining: it
   usually means a GPU or adapter appeared/disappeared on the machine, not a behaviour change.

A future `tools/baseline.rs` (or a `cargo test -- --format json` wrapper) would produce the file
directly; `tools/baseline.ps1` implements these rules today and `docs/dev/baseline.md` explains when
to re-record.
